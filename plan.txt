## 2. Database Schema (`fable_data.db`)

SQLite tables are created using `STRICT` mode (native to modern SQLite versions). No prefix or guilds table is needed since the prefix is global.

### 2.1 `users`
```sql
CREATE TABLE IF NOT EXISTS users (
    user_id     TEXT PRIMARY KEY,
    balance     INTEGER NOT NULL DEFAULT 0,
    xp          INTEGER NOT NULL DEFAULT 0,
    level       INTEGER NOT NULL DEFAULT 1,
    last_daily  INTEGER NOT NULL DEFAULT 0,
    created_at  INTEGER NOT NULL DEFAULT (unixepoch())
) STRICT;
```

### 2.2 `collection`
```sql
CREATE TABLE IF NOT EXISTS collection (
    user_id      TEXT NOT NULL REFERENCES users(user_id),
    insect_id    TEXT NOT NULL,
    count        INTEGER NOT NULL DEFAULT 1,
    first_caught INTEGER NOT NULL DEFAULT (unixepoch()),
    PRIMARY KEY (user_id, insect_id)
) STRICT;
```

## 4. Phase Plan

- [x] **Setup & Version Control:** Init git repo, write `.gitignore`, configure `package.json`
- [ ] **Phase 1 — Core Prototype & Configurations:**
  - Create `src/configs/config.json` & `src/configs/insets.json`
  - Create `src/db/index.js` utilizing Node 24 `node:sqlite` (DatabaseSync)
  - Create Command Registry loader (`src/handlers/commandHandler.js`) using dynamic ESM file URLs
  - Create event dispatcher (`src/handlers/messageCreate.js`) with static prefix resolve & basic error bounds
  - Create `src/index.js` bot runner (using discord.js client)
- [ ] **Phase 2 — Economy & Social Commands:**
  - Write `balance`, `daily`, `give`, `profile`, and `leaderboard` commands
- [ ] **Phase 3 — Insect Catch & Collection:**
  - Write `catch`, `collection`, `insectdex`, `sell`, and `release` commands
- [ ] **Phase 4 — Execution & Validation:**
  - Verify SQLite transactions, upsert queries, leveling mechanics, and overall stability.
